# Pecut AI - Progress Log

## 2026-09-23 - Project start

**Goal:** A joke desktop app (Windows / Linux / macOS) that shows an animation of someone
whipping the AI agent every time an AI prompt is running.

**What was asked:**
- Detection through Claude Code hooks (starts when a prompt is sent, stops when Claude is done).
- 5 original GIFs in different art styles, one of them pixel art (the rest my choice).
- As many options as possible, randomized, available in 2 languages: Indonesian and English.
- Whip sound "CTARR!", random nagging text, lash counter, tray icon, draggable window.
- Its own conda env `pecut_ai`.

**Steps:** make the GIFs and sounds with code -> write the hook and its installer -> build the
overlay app and tray menu -> test end to end with a real Claude Code prompt.

All the art and sound is original and generated by code (no images or sounds downloaded from
the internet), so it is safe to share on GitHub.

### How it knows the AI is working (plain explanation)

1. You send a prompt, and Claude Code runs the `UserPromptSubmit` hook, which calls
   `hook.py start`.
2. `hook.py` writes a small marker file, `~/.pecut_ai/sessions/<session_id>.json`.
3. The app checks that folder every 0.4 seconds. If at least one marker exists, the whipping starts.
4. Each time Claude uses a tool (`PostToolUse`), the marker is refreshed so it counts as still working.
5. When Claude finishes (`Stop`), waits for you (`Notification`), or the session closes (`SessionEnd`),
   the marker is deleted. The foreman says a "done" line and then disappears.

*Example:* you open 2 Claude Code windows and both are working. That makes 2 marker files, so
the tray shows "Whipping 2 agent(s)". One finishes, leaving 1 marker, so the whipping continues.
Both finish, leaving 0 markers, so the window disappears.

Safety net: a marker that has not been refreshed for 10 minutes (for example because you pressed
Esc mid-answer, which skips the `Stop` hook) is removed automatically.

### Menu options (tray icon or right click on the animation)
- **Animation style:** Random per prompt (default) or one of the 5 styles. Double-clicking the animation also switches style.
- **Language:** Indonesia / English / Mixed (each line picks a language at random).
- **Size:** 50% / 75% / 100% / 125% / 150%
- **Whip speed:** Relaxed 0.75x / Normal 1x / Brutal 1.5x / Slave driver 2x
- **Opacity:** 100 / 85 / 70 / 50%. **Volume:** 25 / 50 / 75 / 100%
- Toggles: whip sound, nagging text, counter, "CTAR!" text, always on top
- Manual whip (demo mode), Stop whipping now, Reset position, Reset counter
- Install / remove Claude Code hooks, Quit
- Drag with the left mouse button to move the window. Its position is remembered.

Settings are saved in `~/.pecut_ai/settings.json` and the counter in `~/.pecut_ai/stats.json`.

### How to use it
```
conda create -n pecut_ai python=3.11
conda activate pecut_ai
pip install -r requirements.txt
python -m pecut_ai.installer install     # one time: install the Claude Code hooks
python run_pecut.py                      # start the app (it lives in the tray)
python run_pecut.py --demo               # try it without the AI
python -m pecut_ai.installer uninstall   # remove the hooks
```

## 2026-09-23 - Made the app much lighter on CPU

**Asked:** the animation sometimes made the laptop lag. Make it use as little CPU/RAM as possible
and stay portable. Is C or C++ needed?

**Answer:** C/C++ is not needed. The drawing itself already runs inside Qt, which is C++. The slow
part was *how much work we asked Qt to do per frame*, not the language.

**Before vs after** (measured with psutil over 20 seconds, share of one CPU core):

| State | Before | After |
|---|---|---|
| Idle | 0.1% | 0.0% |
| Whipping, sound on | 20.3% | 2.0 - 4.8% (3 runs) |
| Whipping, sound off | - | 1.4% |
| Battery saver (12 fps) | - | 1.6 - 2.1% |
| RAM while whipping | 78 MB | 72 MB |

**What was slow and what changed (plain explanation):**
1. The window was redrawn about 58 times per second (a 30 ms timer *plus* every GIF frame). Now
   one timer follows the GIF's own speed: 25 times per second, and only the GIF area is redrawn.
2. Every redraw rebuilt everything from scratch: resized the GIF picture, cut the rounded corners,
   drew the border, built the speech-bubble shape and wrapped its text. *Example:* in 1 minute
   the same bubble was built about 3,500 times. Now each frame is prepared once when the style
   loads (24 frames) and the bubble only when its text changes (about every 3.5 seconds).
3. Sound used QtMultimedia, which keeps extra audio threads alive. Now it uses the OS's built-in
   player (`winsound` on Windows, `afplay` on macOS, `pw-play`/`paplay`/`aplay` on Linux). The
   volume is applied by saving a quieter copy of the WAV once in `~/.pecut_ai/cache/sounds/`.
4. Checking for Claude sessions went from every 0.4 s to a folder watcher (reacts instantly), plus
   a safety check every 3 s. The tray tooltip is only updated when its text changes.
5. New menu option **Battery saver**: plays every other frame (12 fps), off by default.
6. `requirements.txt` now uses `PySide6-Essentials` (smaller install, no multimedia module).

**Files:** `pecut_ai/overlay.py` (rewritten rendering), `pecut_ai/sound.py` (new, portable sound),
`pecut_ai/app.py` (watcher, tooltip, menu toggle), `pecut_ai/settings.py` + `pecut_ai/phrases.py`
(`eco_mode` setting and its menu text), `README.md`, `requirements.txt`.

**Verified:** benchmark above; screenshots look the same as before (bubble, CTAR!, counter,
border, sharp on a 125% display); a real hook `start` -> `stop` run showed the window within
0.4 s, counted lashes and hid after the linger time; a second copy of the app is still refused
("Pecut AI is already running.").
